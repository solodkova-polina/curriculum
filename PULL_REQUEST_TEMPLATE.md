# Чек-лист перед отправкой на ревью

### 1. Сборка и запуск
- [ ] Проект собирается без ошибок (`build` / `compile`).
- [ ] Код проверен вручную и локально всё работает.
- [ ] Удалены все `console.log`, `print`, `debugger` и временные логи.
- [ ] Убран весь закомментированный код и старые «заготовки».

### 2. Git и состав изменений
- [ ] Ветка подтянута из свежей `main` / `develop`, нет конфликтов.
- [ ] Название ветки и коммитов содержат номер задачи (Jira / YouTrack).
- [ ] В `.gitignore` добавлены конфиги IDE, `.env` файлы, секреты и локальные билды.
- [ ] В PR/MR попали только файлы по вашей задаче, нет случайно задетых чужих файлов.

### 3. Стиль и качество кода
- [ ] Линтеры и автоформатирование запущены, ошибок нет.
- [ ] Переменные и функции названы понятными словами (без `data1`, `temp`, `a`).
- [ ] Нет хардкода: строки, URL и «магические числа» вынесены в константы.
- [ ] Добавлена обработка ошибок и базовые проверки на `null` / `undefined`.

### 4. Тесты и оформление
- [ ] Все существующие автотесты проходят.
- [ ] Написаны новые unit-тесты на ваш функционал (если требуется).
- [ ] В описании PR есть ссылка на задачу, краткое пояснение правок и скриншоты (для UI).
